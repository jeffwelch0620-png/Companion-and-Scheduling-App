# Authority and receipt-ledger composition — isolated mechanics prototype

The new bridge combines the persisted authority prototype with the isolated receipt-only D1 ledger. No current app route, live migration or UI imports it. All tests use fictional principals, reviewed fixture mappings and an isolated database.

The bridge takes authenticated user identity, organization/store/department binding, reviewed product/location mapping and a clock from the trusted server boundary. None may come from request identity selectors, roles, titles, capability flags, receipt timestamps or client-provided `canReceive`. It loads verified persisted principal/membership/grants, derives the actor from the proof’s person identity, and reconstructs receipt authority rather than forwarding client fields.

This is deliberately a **department-service mechanics test**, not the finalized receiving permission policy. Authority currently has `foh.service` and `boh.service`, but no receipt-specific action. The server fixes that selection to the reviewed department. A separate persisted fixture binding identifies the requesting person, organization, exact physical source/destination, destination’s authority store and stock mapping. This demonstrates explicit designation and scope instead of inferring that every manager can receive every product.

The original ledger guard is a throwing `CHECK(ok=1)` inside an atomic D1 batch. The bridge adds persisted authority and requester/storage predicates to that guard; receipt, stock debit/credit, movement history and request result all share the transaction. Principal/member/grant revisions, active status, schedule-only restrictions, coverage expiry and requester binding are rechecked. A revoked grant after proof load therefore aborts the whole stock save.

The bridge also guards both original/prior receipt reads, including replay after a caught transaction failure. Revocation after initial authorization cannot return a previously saved receipt. It rebuilds authority values with a fresh server clock immediately before the ledger batch, after awaited binding/prior reads, so coverage expiring during those reads is rejected. This is a last-moment server-clock prototype; a production database adapter should use the database transaction’s own time to remove remote execution-delay ambiguity.

Tests verify explicit BOH, FOH and owner grants; receipt actor reconstruction; independent owner, consuming restaurant, production and physical storage; title/admin/client spoof rejection; wrong department/identity/organization; expired coverage; grant/member/principal/requester revocation between proof and commit; expiry after precheck/prior read; and revoked prior-receipt replay. Rejected operations leave stock, receipts, movement history, receipt heads and retry records unchanged. Authority-revocation history itself is intentionally preserved.

Remaining integration gaps: approve a receipt-specific action and requesting-manager policy; verify real authenticated principal provisioning and organization/physical-location mapping; deploy approved schema/adapter through its normal review; add authority composition to correction/reversal and other Food actions; and verify hosted transaction/time behavior. The fixture does not establish live accounts, permissions, Supabase or a complete organizational storage model. No external changes or deployment.
