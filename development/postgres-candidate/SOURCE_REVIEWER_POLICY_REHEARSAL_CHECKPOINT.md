## Supplied snapshot and supported operations

A version-1 snapshot supplies exactly one organization/store/viewer, an account link, session, organization-authority evidence and a bounded designation list. Identifiers are synthetic UUIDs. It supplies person/account-link/organization/store eligibility counters and a strict lifecycleVerified boolean on each of those four sources, record/policy revisions, the designation's captured vector, total active-membership count and global workspace revision. Extra keys, unsupported levels/actions/families, invalid booleans/counters, duplicate identities or person/store/family designations, sparse/overlong arrays and unreviewed shapes refuse with a fixed data-free TypeError.

Bounds of 100 designations and 100 author UUIDs are technical rehearsal safeguards, not S05 production limits. This module does not load or truncate a real roster, designation directory or source file.

| Export | What the rehearsal evaluates | What it does not implement |
| --- | --- | --- |
| rehearseSourceReviewer | Supplied session/person/link/scope eligibility; organization owner/enabled-admin path; explicit store/family review versus review_and_certify; captured/current eligibility equality; self-revocation eligibility | Token/session/provider validation, new grants/restores/revokes, context certification, reason/revision command validation, authorization persistence |
| rehearseSourceReviewerFinalAccess | Initial and final supplied snapshots must both be eligible and have the same relevant access fence | Real REPEATABLE READ/READ COMMITTED transactions, provider-event collection, snapshot transport or protection against a commit after the final check |
| rehearseSourceReviewerAdvisories | Last active-membership count crossing to zero or person becoming inactive proposes fixed advisory kinds | Owner list, durable advisory items, lifecycle event IDs, queue deduplication, outbox delivery or automatic revocation |

The source.review/source.certify distinction follows R07; review_and_certify is explicit, and a qualified author is not disqualified from certifying their own context. Supplied author UUIDs are shape-checked audit context only and never create authority. Scope matches organization/store/family/person; a manager title or membership count never substitutes for a designation. Organization owners/admin do not need fictitious employment or a designation vector.

Reads and certification, including owner/admin policy paths, require lifecycleVerified=true separately for person, accountLink, organization and store. Any unverified source returns lifecycle_unverified, both initially and at the final check; missing/non-boolean evidence is invalid input. These remain supplied fictional assertions, not lifecycle verification. A designee's captured eligibilityRevision must match all current counters even on a fresh request after lapse/re-enable. Explicitly updated fictional restore snapshots demonstrate the comparison, not a working restore command. Organization-policy reads use their current policy/session checks. Ordinary logout/session expiry affects the supplied session, not the durable vector.

Self-revocation is a narrow relinquishment eligibility check on the viewer's own explicit record. It does not require certification or a current captured designation epoch; it does require current eligible personal identity/session/lifecycle evidence. An inactive organization or store does not prevent this relinquishment check. Only person/accountLink lifecycle evidence is required for relinquishment; organization/store lifecycle evidence, active state and eligibility-counter changes are not access gates for this narrow action. Organization/store identifiers, store-to-organization binding and owned designation scope must still match. Another person's record is refused even for an owner using this specific action. Already-revoked returns an eligible no-op proposal with noop:true; all other decision results have noop:false; no audit/receipt is written and no authority is restored. Actual reason, revision, replay and person-level restore controls remain requirements of the future command.

For reads/certification, the final-access fence includes the relevant person/link/session, organization/store policy and selected designation. Self-revocation instead fences personal identity/link/session, immutable organization/store bindings and the owned designation; organization/store inactivation or lifecycle uncertainty cannot prevent relinquishment. Personal-session/link or designation changes still refuse it. A review sees a selected designation revision or scope change; an unrelated family's designation revision, global workspace write or employment-count change does not invalidate it. Revoke/restore between snapshots changes the fence even if both endpoints are eligible. Relevant operational target/configuration revisions need their separate coherent data snapshot; they are not implemented by this access-only model.

session.revision is an application-owned semantic access/session-invalidation revision, not a token-refresh generation. Routine access-token refresh, token expiry renewal or last-seen updates must not advance it. Revocation or another authorization-relevant session change must advance the revision or make the session ineligible; the rehearsal checks the resulting supplied snapshot. No token bytes or refresh metadata belong in its fence.

Advisories require an active owned designation in the after snapshot. If the last designation is revoked in the same transition as employment ending or person inactivation, no advisory is proposed for that former reviewer. A retained active designation still produces the appropriate advisory; no automatic revocation follows from employment changes.
